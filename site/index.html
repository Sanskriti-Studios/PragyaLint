Why PragyaLint

Same idea as vulture or ruff's unused-import checks — different guarantees.

Reachability, not heuristics

Builds a real module graph from your entry points instead of guessing from naming conventions or a confidence percentage pulled from nowhere.

Dynamic-dispatch aware

Recognizes getattr(), dispatch tables, and exec/eval — and downgrades confidence project-wide instead of confidently deleting a function that's actually alive.

Test-suite safe by default

Understands pytest's own discovery convention (test_*.py, conftest.py) so it never proposes deleting your tests as "unreachable."

Zero dependencies

Built entirely on the standard-library ast module. No parser to ship, no supply-chain surface to audit.

Pure Python • ast-powered

PragyaLint uses the Python standard-library ast module to parse and analyze code. That means a complete, battle-tested parser with zero external dependencies and clean distribution via PyPI or pipx.

Inspired by OptiPrune

PragyaLint brings the same concept as OptiPrune (a dead-code analyzer for TypeScript/JavaScript) to the Python ecosystem.
